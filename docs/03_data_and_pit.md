## 2. Point-in-Time 规则（规格书第 68 节）

1. 财务数据可见时间 = 公告日 `f_ann_date`（缺失时用 `ann_date`），**不是**报告期结束日。
2. 同一报告期存在多次公告（更正/重述）时，只保留**最早**公告，避免后见之明。
3. 载入数据集时统一过滤 `ann_date <= as_of`；报告期 2026Q3 在 2026-09-30 尚未披露，
   因此最新可用报告期为 **2026Q2**（与事实一致，脚本已验证 `fina_indicator_vip(20260930)` 返回 0 行）。
4. 同比/环比/加速度全部在"同一可见时点下已公告的历史"上计算，不使用未来季度数据。
5. 价格类因子只使用 `as_of` 及之前的行情。

## 3. 单季度化口径

利润表与现金流量表是**累计口径**，必须先单季度化再做同比/环比：

```
Q1 单季 = Q1 累计
Q2 单季 = Q2 累计 − Q1 累计
Q3 单季 = Q3 累计 − Q2 累计
Q4 单季 = Q4 累计 − Q3 累计
缺少上一季累计 → 返回 NaN（不猜测、不填充）
```

同比统一为 `(本期 − 去年同期) / |去年同期|`，基期为亏损时表示亏损收窄/扭亏的改善幅度；
口径与 `scripts/verify_sample.py` 的独立重算一致（20/20 通过）。

## 4. 偏差控制

| 偏差 | 处理 |
|---|---|
| 幸存者偏差 | 股票池包含 L/D/P 三种状态（含退市/暂停） |
| 未来函数 | 财务按公告日、行情按交易日截断；数据集加载即过滤 |
| 一次性收益 | 用 `扣非净利润` 与 `归母 − 扣非` 差额识别（`one_off_ratio`、`dedt_gap_ratio`） |
| 低基数 | 计算 `low_base_ratio` 并在过滤器与卡片中**显式说明**（不直接判定为假反转） |
| 并表变化/会计政策变化 | 当前数据源无法识别，已在数据质量报告标注为已知缺口 |
| 行业分类时点 | 使用申万当前成分（`is_new`），历史成分未回填 → 回测时需注意轻微前视（Phase 6 待办） |

## 5. 已知数据缺口（如实标注，不做主观填充）

1. **一致预期（EPS Revision）**：账号无权限，ODS 的"盈利预期变化"用业绩预告区间中枢 + 预告广度替代。
2. **行业高频数据**：开工率/产能利用率/现货价格（有色、化工、钢铁等）不在 Tushare 覆盖范围，
   LIS 中该分项（10 分）**不参与打分**，只记录缺口说明（`lis_data_gap`）。
3. **热度/龙虎榜机构席位**：同花顺热榜、东财人气榜不可用，聪明钱因子只用大单+超大单资金流。
4. **质押/监管调查/造假**：未接入，Risk Block 目前只覆盖 ST 与流动性。
5. **北交所**：可入池（有名称 + 当日有行情），但流动性整体偏弱，仅通过成交额下限过滤。

## 6. 缓存与可追溯

每个数据集落成 `data/raw/<group>/<name>.parquet` + `<name>.meta.json`，元数据包含
`data_source / endpoint / trade_date|period / rows / written_at`；抓取清单汇总在
`data/processed/fetch_manifest.json`。评分输出包含 `data_source / update_time /
is_point_in_time / data_confidence / data_flag` 五个字段（规格书第 67 节）。
